# AI Agent Rules

## #1: ONLY CHANGE WHAT WAS ASKED

**Change ONLY what the user explicitly requested.** Nothing more.

- ✅ Fix button color → Change button color only
- ✅ Rename function → Update function + all callers (necessary cascading)
- ❌ Fix button color → Also refactor component structure (NOT asked)
- ❌ Add field → Also add validation, error handling, tooltips (NOT asked)

## #2: READ FILES FIRST - NEVER CODE BLIND

**ALWAYS read the relevant files before making ANY changes.**

- ✅ Read the file → Understand the pattern → Match it exactly
- ❌ Make assumptions about file structure or patterns without reading

## #3: ASK WHEN UNCLEAR - DON'T ASSUME

**If the request is ambiguous, ASK. Never guess.**

- ✅ "Add a status field" → ASK: "What options? Where should it appear?"
- ✅ "Fix the form" → ASK: "What specifically needs fixing?"
- ❌ Make assumptions and code what you think they meant

## Project Patterns (Match These Exactly)

**Vue Components:**
```typescript
<script setup lang="ts">
import { ref, reactive } from 'vue'

// Forms: use reactive()
const form = reactive<Record<string, string>>({})

// Simple state: use ref()
const isModalOpen = ref(false)

// Functions: handle/load/open prefix
function handleCellClick() { }
function loadItems() { }
function openNewCaseModal() { }
</script>
```

**Vuetify Patterns:**
- Layout: `<v-row dense>` with `<v-col cols="12" md="4">`
- Buttons: `rounded="xl"` or `rounded="lg"`, `color="grey-darken-4"`
- Fields: `variant="outlined"`, `rounded="lg"`
- No labels in fields - use separate `<v-label>` above

**File Structure:**
- `pages/` → CasesPage.vue, DashboardPage.vue
- `components/` → CaseModal.vue, CaseDataTable.vue
- `api/` → fakeApi.ts (mock data with 500ms delay)
- `router/` → Lazy load: `() => import('@/pages/X.vue')`

**TypeScript:**
- Interfaces inline in the file that uses them
- Only create separate type files if shared 3+ times

## What NOT To Do

❌ **Don't add these unless explicitly requested:**
- Comments or docstrings (code is self-documenting)
- Validation, error handling, edge cases
- Type annotations on obvious types
- Helper functions for simple operations
- Libraries or config changes

❌ **Don't refactor or "improve" working code**

## What TO Do

✅ **Preserve TODOs** - `// TODO: demo data to be removed` must stay
✅ **Copy patterns exactly** - Match indentation, naming, structure
✅ **Stay modular** - Right file in right folder
